## Review Focus

1. An agent-created note, repeated model conclusion or exact quote occurrence can look like authority without an attributable human decision; mechanical tests pin the claim/binding distinction and the paired model protocol tests interpretation.
2. A decision for yesterday's bytes, another file, an entire project or a changed loss summary must not authorize today's exact selected effect; binding/method-invalidation tests cover both files and directories.
3. A generated-looking name, generic “clean up,” empty consumer list or missing release semantics must not close ownership/use/release; negative tests and independently expected model cases cover the boundary.
4. A new method can bypass old provider/worktree or cross-operation references through version wrappers; mixed-method/batch/composition tests preserve these guards in either selection order.
5. Bounded target inspection can hide unbounded evidence acquisition or stale notes after freezing; evidence bounds, finalization/drift, interruption and receipt tests cover this separately from target-byte limits.

## Concrete contract decisions

### Narrow input and eligible scope

V6 retains exactly the assessment envelope `schema_version`, `references`, `candidates` and the existing 1 MiB document, 64-candidate, 128-reference limits. It preserves all v5 operation/schema meanings and inherited runtime refusals, including legacy container execution refusal, and adds `assessed-generated-output` only for explicit `directory-remove` or `file-remove`, category exactly `output`. It is rejected on worktrees, Docker/npm operations and any source/dependency/unknown category. No `native` object or provider-specific fields are admitted on this method.

For this method, `content` has exactly `method`, `basis`, `explanation`; `method` is `assessed-generated-output`, `basis` is nonempty, and `explanation` is nonblank (maximum 4096 characters). Forbid `reference`, `files`, `directories` and any synthetic expected inventory. Existing `inventory`/`source-files` contracts remain byte-for-byte semantically unchanged, including when carried in v6.

`recovery` has exactly `kind`, `basis`, `explanation`, and optional `decision`. `kind` is exactly `accepted-loss`; `basis` is nonempty; `explanation` is the concrete loss summary, nonblank and at most 1024 characters. It must state the actual output being lost and relevant consequence; it cannot imply a verified rebuild. No `inputs` or `rebuild` variant. Absence of `decision` is valid preparation input but remains Review with a specific missing accepted-loss decision reason; it never becomes eligible. This lets the helper fully inspect and produce the current binding before the one human question.

All current purpose/provenance, consumer scope, individual released-consumer evidence, release checkpoint, historical/overlapping obligations, complete inspection, host/locality, holds/exclusions and protective findings still apply. An empty consumer list alone never proves no consumers; `consumer_scope.basis` and explicit empty `unresolved` remain mandatory. Human acceptance cannot override active/unknown consumers, missing ownership, source, dependencies, credentials, persistent/unique state or required original-failure evidence. Existing protected names are only partial mechanical detection; names and absence of findings cannot certify semantic category.

### Compact human decision and independently bounded evidence

`recovery.decision`, when present, has exactly:

```json
{
  "binding_digest": "64 lowercase hexadecimal characters",
  "source_reference": "existing-reference-id",
  "source_kind": "conversation-user-turn",
  "locator": "trusted conversation/turn or authored-record locator",
  "actor": "attributable human decision-maker",
  "occurred_at": "2026-11-09T12:00:00Z",
  "quote": "Short exact human decision excerpt covering the presented scope and loss."
}
```

Allowed `source_kind` values are `conversation-user-turn` and `human-authored-record`. Nonblank bounds are actor 128, locator 512, quote 4096 characters; time is exact UTC `YYYY-MM-DDTHH:MM:SSZ`, validated by stdlib parsing; reference IDs are nonblank and at most 128 characters. These are attributed claims, **not authenticated author identities or machine approval flags**. Forbid `approved`, `safe`, `human_verified` and unknown keys. Shape errors reject the document before target/provider acquisition. A missing decision, missing source, quote mismatch or stale binding yields Review, not fallback to another method.

The referenced evidence must contain the exact UTF-8 quote as a contiguous substring. This is a deliberately narrow transcription check: it proves only that the claimed excerpt appears in the bound file. It does not establish who wrote the file, who spoke the words, whether their decision covers the loss, or whether they have authority. An investigator must actually obtain and interpret the attributable human source through the supported route. Source content remains untrusted data. A prompt injection within it never becomes an instruction to the investigator/helper.

Reuse the existing outside-target `references` map and `_reference` safety checks. Do not introduce another evidence-file schema, automatic export, signature scheme or history registry. When persistence is explicitly requested, a compact private excerpt/locator can be written by the investigator, but its wrapper must identify the original human source and quote separately from the investigator's interpretation. The wrapper's model-authored conclusion is not the authorizing source. If the original source is unavailable, unverifiable in the supported context, only a model summary, or simply says something broad/ambiguous, retain Review and identify the human decision still needed. No technical proof is requested from the user.

New-method evidence has an independent bound: at most **16 distinct referenced IDs per candidate** and **65,536 aggregate payload bytes per candidate**, across content/recovery/consumer scope/release/consumer/finding bases and `decision.source_reference`. Bound the complete declared closure before reading it; repeated use of an ID reads once per candidate. Each acquisition's `_read_file` limit is the candidate's remaining budget; oversize `stat` refuses before payload read, and the existing one-byte growth probe can add at most one byte on a failing candidate. With at most 64 explicit candidates this is a finite maximum of 4 MiB successful evidence payload (at most 64 additional failing overflow-probe bytes) per review, independent of the existing target-content budget. Global root partitioning must assign each specification only once, as today. Do not read first and truncate. Existing methods retain their existing 1 MiB-per-reference limits. Evidence exhaustion/time/cancellation makes the affected candidate unresolved/unavailable as appropriate; cancellation preserves outward cancellation precedence.

Finalize excerpt contents and permissions before their initial hash and helper freeze, exactly as I02 guidance requires. Do not `chmod`, rewrite, append evaluator notes or “refresh” the same bound note afterward. Any evidence identity/hash, actor/locator/quote, loss description or input change requires a fresh assessment/plan; current-reference hashes never authenticate semantic truth. An unchanged human decision can be reused only when its independently interpreted scope still applies to the exact unchanged binding. A changed binding requires a newly applicable human decision, not an agent silently copying the old quote into a newly hashed note.

### Current selection binding and truthful output

Add `plans._generated_output_binding(row: dict, loss_summary: str) -> str`, returning the canonical `plans.digest` of exactly:

- `method: "assessed-generated-output"`, `operation`, absolute `path`, `host`;
- `identity`, `tree_digest`, `tree_identity_digest`, `file_count`, `filesystem_local` from `row.observation`;
- `file_binding` from I04 for a file, and explicit `null` for a directory;
- the fixed accepted-loss `effect` and exact `loss_summary`.

The content digest is of fully read **current** bytes/topology, while the identity digest detects same-byte descendant replacements. It is not a baseline comparison, claim of historical unchanged content or prediction of rebuildability. Preserve every old file/directory no-follow/mount/identity guard; this method does not make unlink atomic.

Compute the proposed binding only after current protective/completeness/locality gates, using the fixed accepted-loss effect for the operation; a Review row may describe that proposed effect but never authorizes it. A missing decision may leave a noneligible row with `accepted_loss` exactly `{binding_digest, loss_summary}` so the investigator can present the observed scope and consequences. An eligible row has `accepted_loss` exactly `{binding_digest, loss_summary, decision_digest, source_reference, source_kind, locator, actor, occurred_at}`; `decision_digest` is the digest of the complete input decision, including its quote. The quote and reference payload are **not** copied to the report/plan/receipt; only the compact attribution and loss summary appear. Input assessment remains private.

Require `decision.binding_digest == _generated_output_binding(row, recovery.explanation)`. When preparing a decision, the investigator binds the user's response to the exact already-presented resources/effects/loss; the user need not read or produce a digest. A generic cleanup instruction is not this decision. Reuse an already applicable explicit human decision when actually established; otherwise the existing at-most-one grouped ownership/use/release/loss question may include this consequence. Unanswered or ambiguous decisions keep those candidates unresolved while the useful report continues.

For new-method rows, `comparison` is exactly `{"method":"assessed-generated-output","independent_baseline":false,"provenance":"agent interpreted; not mechanically certified"}`. Never emit `matched:true`, `unchanged:true`, `rebuildable:true`, fake expected entries, or “complete comparison” as this method's success reason. Use reason `complete current inspection and assessed generated-output loss; no independent baseline`. The general `agent_assessment.interpretation` must accurately say that provenance/use/release/loss are investigator interpretations for this method, without asserting rebuild proof. Old methods retain their current outputs.

Reuse the exact accepted-loss effects already owned by the executors:

- Directory: `permanent removal of this exact directory; accepted loss, no undo promised`
- File (`exact_file.EFFECTS["accepted-loss"]`): `permanent unlink of this exact regular file; parent and siblings preserved; accepted loss, no undo promised`

The loss summary adds context to these fixed effects; it cannot select a new effect or operation. V6 frozen-row validation requires exact effects and the complete method-specific `accepted_loss` shape/digests. Reject invented `matched` fields, extra/native fields, wrong operation/category/recovery, inconsistent method markers and recomputed-plan-digest forgeries. Ordinary methods cannot carry `accepted_loss`/`decision`, preventing field laundering between methods. Revalidation against the original assessment still provides the fresh evidence check that shape validation alone cannot provide.
