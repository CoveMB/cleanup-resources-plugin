# Legacy Docker Container Removal Refusal Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development under the coordinated execution method. The three sequential independent plan reviews are complete; implementation reviews remain required. Steps use checkbox (`- [ ]`) syntax. The controller assigns workers and reviewers; no recursive delegation.

**Goal:** Prevent executable legacy container removal whenever a complete no-writable-change predicate is unproved, which currently means every `docker-container-remove` candidate, while preserving saved-plan interpretation, observation-only reconciliation and other operation contracts.

**Architecture:** Keep one provider-free refusal policy in the existing Docker owner, used by direct inspection before `LocalDocker` construction and by execution-only admission at the very start of `cleanup._revalidate`. Admit all selected rows before completed-resource observations, assessment rereads, ordinary review/snapshots or per-item provider revalidation; thus any selected legacy container refuses the whole batch before those acquisitions, regardless of order. Give the existing review owner a specific payload-free Unavailable reason. Keep v3/v4 parsing, old pending receipts and the separate observation path readable; never put this support policy in the shared selection/resource validators or reconciliation.

**Tech Stack:** Python 3.12+ standard library; current unittest suites and actual extracted allowlisted ZIP; finite fresh-model interpretation observation with ordinary disposable filesystem fixtures and fictional container records. No Docker runtime required to qualify this negative guard.

**Spec:** [Canonical design](../../superpowers/specs/2026-10-19-context-aware-resource-cleanup-design.md) §§4–7; [continuation plan](plan.md), [QA plan](qa-plan.md), [accepted I03 plan](i03-worktree-lineage.md), and [README “Selected native Docker cleanup”](../../../README.md#selected-native-docker-cleanup). ### Why this is a correction

Pinned Moby v28.0.0 overlay2/containerd Changes compares metadata and can omit same-length changed bytes with restored mtime. Legacy SizeRw admission accepts every nonnegative integer; native digest binds inspect JSON, not writable bytes. Provider-double evidence demonstrates actual legacy eligibility/revalidation reaching a mocked nonforced rm boundary for SizeRw 0 and 4096. It does not reproduce Docker loss. Optimized overlay2 size and containerd usage can be independent observations, but positive size is accepted; naive size can share the omission. Neither SizeRw-zero nor created state is a proved substitute predicate.

The documented tested Docker 29.8.2 source remains unresolved: connected GitHub pinned requests returned “No commit found for the ref v29.8.2.” Do not assert that build is affected, fixed, nonexistent or equivalent to v28. The helper has no qualified provider/backend restriction or complete alternative predicate. Therefore conservatively refuse all legacy container execution now. A future independently proved route may restore eligibility through separate review; no route is invented here. Accepted-loss remains contextual recovery evidence, never an override for unobserved writable data. The tradeoff is deliberate loss of container-cleanup availability, including truly disposable empty fixtures, to preserve the existing safety promise.
