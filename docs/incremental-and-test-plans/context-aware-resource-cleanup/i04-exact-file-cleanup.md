## Contract decisions

### Input and eligibility

A v5 document has exactly the existing `schema_version`, `references`, `candidates` envelope, with existing 1 MiB/64-candidate/128-reference bounds. V5 includes existing directory/worktree/Docker/npm schema meanings plus `file-remove`, subject to all runtime refusals in the accepted predecessor; it does not reenable legacy container execution disabled by the Docker correction. A file specification uses existing base assertion fields plus `operation`; forbid `worktree`, `docker`, `npm`, `native`, arbitrary commands, approval/status flags and unknown fields. Paths are exact literal paths under the existing task/project/global semantics; never expand glob characters. Global paths remain absolute. Duplicate/alias/overlapping selections remain rejected.

File eligibility is initially **category `output` only**, with `content.method` exactly `inventory` or `source-files`, and existing purpose, source provenance, release, complete consumer scope and recovery claims. Use current `rebuild` with retained inputs or `accepted-loss` with evidence; neither substitutes for independent content evidence. Source, dependencies, credentials, persistent/unique state, original-failure evidence and unresolved ownership remain protected/noneligible. Names are not proof of harmlessness; existing assessment interpretation limits remain explicit.

Represent the target as one normalized inventory entry whose `path` is the exact leaf basename, `kind` is `file`, with mode, logical size and complete SHA-256. A retained inventory must contain exactly that singleton; a source-files mapping must map exactly that basename to its independent reference and have no directory entries. Keep `_expected_entries`' existing rejection of `.` and unsafe paths. Include the target leaf's identity in the snapshot `entries` so `_reference` rejects self-reference/inode aliases. Do not scan parent contents or manufacture an inventory from current bytes to qualify a real candidate.

Use exact effects determined by the existing recovery gate:

- `permanent unlink of this exact regular file; parent and siblings preserved; rebuild required`
- `permanent unlink of this exact regular file; parent and siblings preserved; accepted loss, no undo promised`

`file-remove` rows carry no `native` object. Their ID is `plans.digest({"operation": "file-remove", "path": absolute_path})[:16]`. Their ordinary `observation` fields remain `complete`, `identity`, `tree_digest`, `tree_identity_digest`, `file_count`, `filesystem_local`, `size`, `coverage`, plus **`file_binding`**. `file_count` is one for eligible files. The tree digests describe the singleton normalized file entry, not a parent tree.

`identity` extends `review.file_identity(stat)` **only for this operation** with `nlink`, `uid`, `gid`, `flags`; require a regular file and `nlink == 1`. `file_binding` has exactly `ancestors` and `mount`: `ancestors` is the ordered complete chain from `/` through the target's parent, each record exactly `{path, device, inode, mode, uid, gid, flags, mount}`; `mount` is the selected target descriptor's observed mount identity. Bind every ancestor, not just review roots and immediate parent. Retain directory stable identity/security/mount fields; deliberately exclude directory size/mtime/ctime/nlink, which ordinary sibling removal changes. This is an identity binding, not an atomic snapshot or an assertion that every directory metadata bit is invariant. Recheck current effective permissions and flags independently.

### Narrow owner and reuse decision

Create `skills/task-disk-review/scripts/devspace/exact_file.py`. Existing directory `review_task`, `cleanup._snapshot` and `_remove` assume directory roots/enumeration/rmdir. Altering those assumptions in place risks changing v1–v4 semantics; a small file-specific owner is proportionate. Reuse `review.file_identity`, `mount_identity`, `local_filesystem`, `protection`, `descriptor_traversal_available`, `report.new_report`, `plans._assess` and the cleanup transaction/permission/durability capabilities. Keep `review.file_identity` unchanged for all old operations.

Produce these interfaces:

- `exact_file.OPERATION = "file-remove"`; `EFFECTS` is a fixed mapping keyed by `"rebuild"` and `"accepted-loss"` with the two strings above.
- `review_file(path: Path, *, max_content_bytes: int, timeout: float, cancelled=None) -> dict`: a report-shaped singleton snapshot consumed by existing `_entries`/`_assess`; fixed sanitized refusal reasons, actual read counts, explicit incomplete/cancelled status.
- `validate_row(row: dict) -> None`: validate the frozen eligible file operation, exact effect, singleton observation and complete binding field/type shapes; no provider execution or content read. Noneligible file discovery/assessment rows may lack a completed observation and cannot be selected.
- `snapshot(row: dict, limits: dict) -> dict`: reread the exact file, compare its full frozen content/identity/binding, and preflight actual mutation capabilities/permissions/durability; no deletion.
- `remove(row: dict, limits: dict) -> None`: retain checked descriptors through complete reread/final checks, perform exactly one `os.unlink(leaf, dir_fd=parent)`, then durably flush the surviving parent. No directory fallback.
- `observe(row: dict) -> str`: no payload reads/effects; return `absent-parent-retained`, `same-identity-contents-unverified`, `replaced`, or `unknown`. The first requires all frozen ancestor bindings still matching and absence of the exact leaf; missing/replaced ancestors yield `unknown`. For a present leaf, differing device/inode/type means `replaced`; the original regular single-link inode with matching security identity may be `same-identity-contents-unverified` without asserting unchanged bytes; unsafe link/security drift or unavailable inspection is `unknown`.

Keep descriptor walking/hashing internals private to this module. Use local imports for existing `plans`/`cleanup` capability functions where necessary to avoid import cycles, consistent with provider modules; do not make a new cross-operation framework. Share the module's own bound-open/read/check implementation among `review_file`, `snapshot`, `remove` and `observe`, so last-boundary checks cannot silently diverge from review. A context-managed retained chain must close all descriptors on every error/cancellation path.

### Descriptor and mutation rules

Normalize lexically to an absolute path, do not resolve away symlink ancestors. Check protected names/ancestry and policy before payload acquisition. Traverse each component with `O_DIRECTORY|O_NOFOLLOW`; bind every opened directory against its no-follow directory-entry identity. Use existing search-only ancestor access when supported; acquire a checked readable parent descriptor for permission/flush operations rather than assuming an `O_SEARCH` descriptor can fsync. Check the retained chain again through a fresh no-follow walk immediately before unlink to detect a moved/replaced prefix.

Stat the leaf without following it before open; refuse links, hardlinks, directories and special files before payload reads. Open with `O_RDONLY|O_NOFOLLOW|O_NONBLOCK`; compare pre-open stat, opened identity, named identity and nlink before/after hashing and just before unlink. Bind the target mount; require parent/target mount agreement and supported locality before payload reads. Ancestors can legitimately cross mounts: bind each ancestor's mount separately rather than requiring every ancestor to share the target's device. Known sync components retain existing refusal semantics. Account for all bytes including the bounded overflow probe; stop on timeout/cancellation, growth, partial read or identity drift. Reuse existing report size/accounting conventions without counting the file twice in outer metadata totals.

Mutation still starts with `cleanup._capabilities()` and the actual local APFS test in `_supported_filesystem`. In `snapshot` and immediately before unlink, check target and parent immutable/append flags, current effective parent write/search access, parent/target filesystem/mount capability, all frozen identities and `_sync_file(parent)` before the first effect. No permission change, mount operation, provider subprocess or fallback. After unlink `_sync_file(parent)` must succeed for a completed outcome; post-effect failure is unknown/partial and leaves pending recovery state. Do not rmdir the parent or enumerate/remove neighboring entries. The final check/unlink remains vulnerable to an unrelated same-user writer; preserve that warning prominently.
