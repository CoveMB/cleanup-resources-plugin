# Task, project and general disk review

Review a selected task, project, configured global scope or an expressly general local disk-cleanup request. Ask for scope only if it cannot be resolved from the request and trusted context. Disk troubleshooting, performance diagnosis and filesystem repair are outside this skill. Do not infer thread identity from names/environment/Git. Project mode inventories linked worktrees only from a selected worktree root; task/nested scope never expands to its parent repository or becomes a general scan.

Before the initial helper review, bind applicable holds and exclusions to the intended absolute resource paths from the selected scope and trusted context. Pass those absolute paths to every `--hold` and `--exclude`: relative options resolve against the helper process's working directory, not `--task` or `--project`, and assessment notes may be written elsewhere. Preserve the same exclusion bindings in other discovery reads. If an intended binding is unclear, leave that resource uninspected and ask only for the needed scope clarification.

Run the bundled helper with Python 3.12+ using its resolved installed path:

```sh
python3 "<skill-directory>/scripts/devspace.py" review --task "<selected-directory>"
```

Add `--json` for structured output. Defaults are 2,000 metadata entries, 12 directory levels and a cooperative 10-second budget. Adjust `--max-entries`, `--max-depth`, or `--timeout` only for the selected task when useful; never silently expand to other roots. Ctrl-C returns a partial cancelled report. Exit 0 means complete metadata traversal, 2 means partial/unknown coverage including unavailable safe traversal, 1 means an invalid or inaccessible selected directory, 130 means cancelled. Parser errors also use 2; inspect their diagnostic before interpreting it as a report.

Use `--project` instead of `--task` for project review. Explain host/scope, unknown thread identity, partial coverage and logical versus allocated estimates. Git discovery remains report-only: inspect staged/dirty/untracked/ignored/locked/detached/local-upstream facts and unknown activity, preserving resume paths. Git filters or unavailable access mean unknown, not inactivity. No fetch. Worktree roots never enter generic directory cleanup; explicitly assessed ordinary linked checkouts use the native path below. Branches and other provider storage remain report-only.

Use `--global --config FILE` for global review; prepare the small existing configuration contract in README from the selected scope. Supply bounded absolute roots/holds/exclusions and known provider storage paths; the helper gains no implicit home/whole-disk scope, conversation loader or package-manager requirement. Without configuration, report unconfigured coverage. Global assessed paths are absolute and reuse the same evidence contract. Known package/Codex storage paths also belong in `--hold`/`--exclude` for task/project review; never treat managed resources as generic directory targets.

Global coverage distinguishes examined, skipped, inaccessible, unavailable and unconfigured locations. Partial or absent provider data is unknown usage. Git inventories come from bounded configured-root discovery; remote resources, synchronization/network/WSL boundaries and unsupported provider state stay report-only. Optional Docker discovery uses an explicitly selected Unix socket via the installed CLI; assessed native selection follows the Docker contract below. No remote context, login, credential probe, installation, blanket pruning or VM manipulation.
